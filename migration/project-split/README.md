## ローカル・公開環境

ローカルの環境変数変更後は開発サーバーを再起動する。

Vercelの環境変数はこの作業では未更新。公開済みサイトを切り替える場合は各サイトに対応するVercelプロジェクトで、以下を設定して再デプロイする。

- `NEXT_PUBLIC_SANITY_PROJECT_ID`: 上記の移行先プロジェクトID
- `NEXT_PUBLIC_SANITY_DATASET`: `production`
- `SANITY_API_WRITE_TOKEN`: 対応するサイトの `.env.local` に保存した専用トークン（ブラウザ公開用の変数名にはしない）

本番Studioを使用する際は各SanityプロジェクトのCORSに該当サイトの正確な公開originを認証付きで追加する。今回設定したoriginは移行元と同じ `http://localhost:3000` と `http://localhost:3333` のみ。

移行元にWebhookは存在しなかったため、自動更新通知は別途設定が必要。サイトには `/api/sanity/revalidate` の受信処理がある。

## 保持データと公開範囲

移行元の2データセット・共有APIトークンは削除や失効を行わず保持する。本番環境などの旧接続先がないことを確認してから整理する。

移行先は移行元と同じ公開データセットであり、プラン変更・課金操作はしていない。今回の移行時点でお問い合わせは0件。お問い合わせを保存する前に、非公開データセット化とサーバー側の読み取り認証への対応が必要。

バックアップ・環境変数の旧値・移行の再開用状態は `/tmp/base11-sanity-split/` に保存（ディレクトリは所有者のみアクセス可能）。秘密情報を含むためGitには追加しない。`/tmp` は永続保存先ではなく、元データセットも復元元として保持する。
